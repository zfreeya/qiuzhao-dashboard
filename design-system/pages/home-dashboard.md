# Home Dashboard — 首页设计规范

> 继承自 [MASTER.md](../MASTER.md) | 页面：首页仪表盘 `/`

---

## 1. 页面目标

用户 3 秒内获取：
1. **当前状态**：投了多少、面了几场、拿到几个 Offer
2. **最近面试**：完整周视图日程，今天/本周有哪些面试或笔试
3. **今日行动**：今天应该完成什么

## 4. 模块规范

### 4.1 Hero 区（顶部状态区）

**统计数据**：仅展示 3 项，删除"进行中"指标。

| 指标 | 数据来源 | 计算方式 |
|------|---------|---------|
| 已投递 | `applications[]` | `applications.length` |
| 总面试 | `interviews[]` | `interviews.length` |
| Offer | `applications[]` | `applications.filter(a => a.status === "已Offer").length` |

| 属性 | 桌面 | 移动 |
|------|------|------|
| 背景 | `bg-gradient-to-br from-brand-700 via-brand-600 to-brand-800` | 同桌面 |
| Padding | `p-6 sm:p-8` | `p-4` |
| 圆角 | `rounded-2xl` | `rounded-2xl` |
| 问候语 | `text-2xl sm:text-3xl font-bold` | `text-xl font-bold` |
| 统计数字 | `text-2xl font-bold tabular-nums` | `text-xl` |
| 统计标签 | `text-xs text-brand-300/70` | 同 |
| 装饰元素 | 移除 blur 光斑（纯装饰，不传达信息） | — |

**内容规则**：
- 显示：日期 + 问候 + 当前阶段(倒计时) + 三项统计
- 下一场面试信息内联在 Hero 底部，不独立成卡
- 已投递和 Offer 来自 Application 表，总面试来自 Interview 表
- 不显示"进行中"指标

### 4.2 面试日程（完整周视图，全宽）

**保留完整的 `ScheduleCalendar` 组件，不降级为列表。**

| 属性 | 值 |
|------|-----|
| 容器 | `card p-6`（全宽，无其他模块并排） |
| 组件 | `ScheduleCalendar`（现有组件，不做结构性改动） |
| 宽度 | 独占整行（原来可能和投递漏斗并排，现在投递漏斗已删除） |
| 日期切换 | 保留 `< 上周` `下周 >` `今天` 按钮 |
| 新建日程 | 保留 `+ 新建日程` 按钮 |
| 日程编辑/删除 | 保留点击日程卡片弹出 `ScheduleEditor` 的交互 |
| 时间轴 | 保留 8:00-21:00 × 7 天网格 |
| 周视图 | 保留完整的 Mon-Sun 列头 + 日期高亮（今日 `brand-500`） |
| 空间态 | 保留空状态提示："暂无日程，点击「新建日程」添加" |

**规则**：
- **不新增**独立日历页作为首页日程的替代方案
- **不修改** `ScheduleCalendar` 组件的内部实现
- **不修改** 日程 CRUD（`scheduleService.ts`）
- **不修改** 日程数据模型（`ScheduleEvent`）
- **不新增** compact/list 模式 prop

### 4.3 三卡片区

**保留现有三卡片结构**：NextBattleCard、AIDiagnosisCard、TodayAdviceCard。

| 属性 | 桌面 | 移动 |
|------|------|------|
| 布局 | `lg:grid-cols-3` 三列等宽 | `grid-cols-1` 单列堆叠 |
| 间距 | `gap-4 sm:gap-6` | `gap-4` |

**待优化项（后续迭代）**：
- 卡片统一白底（当前三卡各自有 amber/purple/emerald 渐变背景）
- 紧迫/成功/AI 状态用左边缘色条区分，而非整卡变色

### 4.4 今日作战计划

**保留现有独立模块**：`ActionCenter` > `ActionCard[]`。

| 属性 | 桌面 | 移动 |
|------|------|------|
| 容器 | `card p-6` | `card p-5` |
| 卡片网格 | `sm:grid-cols-3` | `grid-cols-1` |
| 条件渲染 | `actionPlan.length > 0` 时展示 | 同 |

### 4.5 今日待办

**保持现有结构不变。**

| 属性 | 桌面 | 移动 |
|------|------|------|
| 输入框 + 选择 + 按钮 | 一行 `flex gap-2` | 同 |
| 任务行高 | ≥ 44px | ≥ 44px |
| Checkbox 颜色 | `accent-brand-500` | 同 |
| 空状态 | Sparkle 图标 + "还没有任务，来添加第一个吧" | 同 |
| 已完成 | `opacity-50 line-through` | 同 |

**待优化项**：
- 移动端优先级标签缩写（"高"/"中"/"低" 代替 "高优"/"普通"/"低优"）
- 删除按钮在移动端始终显示（不依赖 hover）

### 4.6 能力画像摘要

| 属性 | 值 |
|------|-----|
| 容器 | `card p-5` |
| 布局 | 紧凑单行：分数 + 图标 + 标签 + 优势摘要 + 链接 |
| 条件渲染 | `abilityProfile` 存在时展示 |

## 5. 首页色彩分配

| 区域 | 背景 | 边框 | 强调 |
|------|------|------|------|
| Navbar | `bg-white/75 backdrop-blur` | `brand-200/50` | 当前页 `brand-50` |
| Hero | `brand-700→800 gradient` | 无 | 白色文字 + Offer 用 amber-300 |
| 三卡片 | `card` (白色) | `brand-200/60` | 紧迫=amber, AI=purple, 建议=emerald |
| 作战计划 | `card` (白色) | `brand-200/60` | P0=red, P1=amber, P2=neutral |
| 面试日程 | `card` (白色) | `brand-200/60` | 今日 `bg-brand-500 text-white` |
| 今日待办 | `card` (白色) | `brand-200/60` | checkbox `accent-brand-500` |
| 能力画像 | `card` (白色) | `brand-200/60` | 分数颜色 = 语义色（emerald/amber/red） |

## 6. 首页模块顺序（最终确认）

```
1. Hero（顶部状态区：问候 + 3 统计 + 倒计时）
2. 三卡片（NextBattle / AI诊断 / AI建议）
3. 今日作战计划（条件渲染）
4. 面试日程（完整周视图，全宽，独占整行）
5. 今日待办
6. 能力画像摘要（条件渲染）
```

移动端顺序与桌面端完全一致，不做重排序。

## 7. 与现有实现的差异

| 模块 | 现状 | 目标 | 改动量 |
|------|------|------|--------|
| Hero 统计 | 3 项统计（可能含"进行中"） | 严格 3 项：已投递/总面试/Offer，删除"进行中" | 小 |
| Hero 装饰 | 含 2 个 blur 光斑 | 移除 blur 光斑 | 小 |
| 投递漏斗 | 可能存在独立的投递漏斗模块 | **删除** | 小 |
| 面试日程 | 全宽周视图，完整 ScheduleCalendar | **保持不变**，占满原"漏斗+日程"整行 | 无 |
| 三卡片 | 独立三卡（含彩色渐变背景） | 保持结构，后续统一白底 | 无→后续中 |
| 作战计划 | 独立模块 | **保持不变** | 无 |
| 今日待办 | 现有结构 | **保持不变** | 无 |
| 能力画像 | 现有结构 | **保持不变** | 无 |

## 8. 实施建议

1. **Phase 1**：删除投递漏斗模块，日程组件占满整行宽度（小改动，直接收益）
2. **Phase 2**：修正 Hero 统计为严格 3 项，移除"进行中"，移除 blur 装饰（小改动）
3. **Phase 3**：后续迭代 — 三卡片统一白底 + 左边缘色条替代整卡背景色

每个 Phase 独立可交付，不影响其他页面。

---

## 9. 明确禁止的改动

以下改动**不在**首页设计规范范围内，不做：

- ❌ 将周日历降级为 N 条近期日程列表
- ❌ 新增独立日历页面作为首页日程的替代
- ❌ 给 `ScheduleCalendar` 组件新增 compact/list 模式 prop
- ❌ 修改日程 CRUD 逻辑（`scheduleService.ts`）
- ❌ 修改日程数据模型（`ScheduleEvent` 接口）
- ❌ 删除或替换 `ScheduleCalendar` 组件
- ❌ 修改 Calendar 内部的周视图、时间轴、事件渲染逻辑
